## Implementation decision

The existing guest entry rendered a large introduction, motion explanation, coaching panel and full side picker before Start. It then explained the loop again in a separate three-step section. The same small product promise can be communicated with fewer decisions.

- Move the start action earlier with a preselected, visible side and native expandable options for side/persona changes.
- Keep data-sharing information immediately before Start and associate it with the button for assistive technology.
- Replace the second generic workflow explanation with a labelled first-draft → reason → rewrite example. It illustrates a causal link, claims no score, and explicitly says the claim is not proven.
- Use the existing semantic colour, type, border and radius tokens. Desktop pairs the introduction/example with practice; mobile places practice before the example.
- Preserve the existing guest state machine, recovery, scoring and account boundary. No questionnaire, dependency for UI, mascot, fake community, invented performance or learning metrics.

Validation and remaining limitations are recorded in the completion report for this change. Full app flows remain outside the accessible evidence.
